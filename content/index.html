    03 Endpoints

    HTTP
    GET /content/ หน้านี้

    สรุปคลังคอนเทนต์ ตัวเลขสด และเอกสาร API

    GET /content/registry.db SQLite

    ฐานข้อมูล metadata ของคอนเทนต์ทั้งหมด

    GET /content/scripts/ ไฟล์ข้อความ

    บทพากย์ทั้งหมดในคลัง หนึ่งไฟล์ต่อหนึ่งบท

    GET /content/horoscope/ JSON

    ข้อมูลดวงรายวันในรูปแบบ JSON

    GET /api/health live

    สถานะรวมและผลตรวจรายรายการ ใช้แสดงผลในหัวข้อ “สถานะบริการ” ตรวจ cdn/star/manifest.json และสิทธิ์เขียนของ content/overrides, content/scripts, content/backups, cdn/star

    Response 
    {
  "status": "ok",
  "version": "1.0.0",
  "checked_at": "2026-08-11T09:00:00Z",
  "root": "/var/www/star",
  "checks": {
    "manifest": { "status": "ok", "detail": "31 days indexed" },
    "content/overrides": { "status": "ok", "detail": "writable" },
    "content/scripts": { "status": "ok", "detail": "writable" },
    "content/backups": { "status": "ok", "detail": "writable" },
    "cdn/star": { "status": "ok", "detail": "writable" }
  }
}
    ทุก check เป็นอ็อบเจ็กต์ { status, detail } โดย status เป็น ok / warn / fail ส่วน status รวมเป็น fail ถ้ามี check ใดล้มเหลว และเป็น warn ถ้ามี check ใดเตือน
    • 200 status เป็น ok หรือ warn
    • 503 status เป็น fail
    GET /api/stats live

    ตัวเลขสรุปของคลัง ใช้เติมตัวเลขในหัวข้อ “ตัวเลขสดจาก API” ทุกค่านับจากไฟล์จริงบนดิสก์ ณ เวลาที่เรียก ไม่มีการแคช

    Response 
    {
  "scripts": 434,
  "days": 31,
  "audio": 0,
  "videos": 0,
  "generated_at": "2026-08-11T09:00:00Z",
  "dates_total": 31,
  "dates_complete": 28,
  "dates_upcoming": 12,
  "scripts_total": 217,
  "overrides_total": 4,
  "published_total": 196,
  "manifest_days": 31,
  "manifest_ok": true,
  "first_date": "2026-08-01",
  "last_date": "2026-08-31",
  "next_date": "2026-08-11",
  "status_counts": { "published": 28, "draft": 3 }
}
    ตัวเลขเป็นเพียงรูปแบบตัวอย่างของ payload — ฟิลด์ scripts / days / audio / videos คงไว้เพื่อความเข้ากันได้กับแดชบอร์ดรุ่นก่อน
    • 200 สำเร็จเสมอเมื่อบริการทำงานอยู่
    • 500 อ่าน manifest.json ไม่ได้หรือข้อผิดพลาดภายใน
    GET /api/manifest JSON

    คืนไฟล์ cdn/star/manifest.json ตามที่อยู่บนดิสก์ ซึ่งเป็นดัชนีรายวันที่หน้าเว็บใช้อ่าน

    • 200 สำเร็จ
    • 404 ยังไม่มีไฟล์ manifest.json
    • 500 ไฟล์ไม่ใช่ JSON object ที่อ่านได้
    POST /api/save-script

    บันทึกบทที่แก้ไขแล้วของหนึ่งวัน ต้องส่ง date, day และ script ครบทั้งสามฟิลด์ เขียนแบบ atomic (temp file + rename + fsync) ลงสามที่พร้อมกัน คือ content/overrides/<date>/<day>.txt, content/scripts/claude_<date>_<day>.txt และ cdn/star/<date>/<day>.txt ถ้ามี override เดิมอยู่ จะสำรองไว้ที่ content/backups/ ก่อนเขียนทับ

    Request 
    {
  "date": "2026-08-11",
  "day": "tue",
  "script": "ดวงของชาววันอังคาร…"
}
    date ต้องเป็น YYYY-MM-DD ที่มีจริงในปฏิทิน · day ต้องเป็นหนึ่งใน sun mon tue wed thu fri sat · script ต้องไม่ว่างและไม่เกิน 256 KB
    Response 
    {
  "ok": true,
  "date": "2026-08-11",
  "day": "tue",
  "bytes": 1284,
  "written": [
    "content/overrides/2026-08-11/tue.txt",
    "content/scripts/claude_2026-08-11_tue.txt",
    "cdn/star/2026-08-11/tue.txt"
  ],
  "backup": "content/backups/2026-08-11/tue.20260811T090000Z.txt",
  "saved_at": "2026-08-11T09:00:00Z"
}
    backup เป็น null เมื่อยังไม่เคยมี override ของวันนั้น
    • 200 บันทึกสำเร็จ
    • 400 body ไม่ใช่ JSON object หรือ date / day / script ไม่ถูกต้อง
    • 403 คำขอข้ามต้นทาง (Origin ไม่ตรงกับ Host)
    • 405 ใช้ method อื่นที่ไม่ใช่ POST
    • 411 ไม่ได้ส่ง Content-Length
    • 413 body หรือ script เกิน 256 KB
    • 500 เขียนไฟล์ไม่สำเร็จ
    POST /api/regenerate

    เผยแพร่ซ้ำ (republish) เท่านั้น — คัดลอกไฟล์บทที่มีอยู่แล้วบนดิสก์ (override ก่อน ถ้าไม่มีจึงใช้ไฟล์ต้นทางใน content/scripts/) ไปยัง cdn/star/<date>/ แบบ byte-for-byte ไม่มีการสร้างข้อความใหม่ด้วย AI หรือวิธีใด ๆ วันที่ไม่มีไฟล์ต้นทางจะถูกรายงานกลับ ไม่ถูกเติมให้ ส่ง day เป็นวันเดียว หรือเป็น "all" (เว้นว่างหรือ null ก็ถือเป็น all) เพื่อทำทั้งเจ็ดวันของวันที่นั้น

    Request 
    {
  "date": "2026-08-11",
  "day": "all"
}
    date จำเป็นเสมอ · ถ้าเป็น all ต้องมีไฟล์ต้นทางครบทั้งเจ็ดวัน
    Response 
    {
  "ok": true,
  "date": "2026-08-11",
  "published": [
    { "day": "sun", "source": "script" },
    { "day": "mon", "source": "override" }
  ],
  "count": 2,
  "note": "republished existing script files; no text was generated",
  "finished_at": "2026-08-11T09:00:00Z"
}
    source บอกว่าไฟล์ที่คัดลอกมาจาก override หรือ script ต้นทาง
    • 200 เผยแพร่ซ้ำสำเร็จ
    • 400 body ไม่ใช่ JSON object หรือ date / day ไม่ถูกต้อง
    • 404 ไม่มีไฟล์บทต้นทางบนดิสก์สำหรับวันที่ที่ขอเลย
    • 409 มีไฟล์ต้นทางไม่ครบ — ไม่เผยแพร่อะไรเลย เพื่อไม่ให้สัปดาห์ไม่สอดคล้องกัน
    • 500 คัดลอกไฟล์ไม่สำเร็จ
    /api ให้บริการอยู่จริงบนโดเมนนี้ ผ่าน nginx ที่ proxy ไปยัง star_api.py บน 127.0.0.1:9001 และยังคงบังคับ Basic Auth เช่นเดียวกับส่วนอื่นของไซต์ — ทุก endpoint ตอบ JSON เสมอ โดยกรณีผิดพลาดจะมีฟิลด์ error และ status

    04 สายการผลิต

    ขั้นตอน offline → เผยแพร่
    1
    คำนวณดวง ขั้นตอน offline

    Swiss Ephemeris คำนวณตำแหน่งดาวและสร้างข้อมูลดวงของวัน รันนอกเว็บ ไม่มี endpoint

    2
    เขียนบท ขั้นตอน offline

    เขียนบทพากย์จากข้อมูลดวงนอกเว็บ แล้ววางไฟล์ไว้ที่ content/scripts/claude_<date>_<day>.txt การแก้ไขภายหลังทำผ่าน POST /api/save-script

    3
    สร้างเสียง ขั้นตอน offline

    Google Chirp3 HD แปลงบทเป็นเสียงพากย์ ไฟล์ที่ได้เก็บไว้ใต้ output/

    4
    ประกอบวิดีโอ แผนงาน

    CapCut ประกอบภาพ เสียง และซับไตเติลเป็นวิดีโอ ยังรอ batch ยังไม่มีระบบอัตโนมัติ

    5
    เผยแพร่ POST /api/regenerate

    ขั้นที่มี endpoint จริงคือการเผยแพร่บทขึ้น CDN ด้วย POST /api/regenerate ซึ่งคัดลอกไฟล์ที่มีอยู่แล้วเท่านั้น ส่วนการส่งขึ้น YouTube, TikTok และ LINE ยังทำนอกระบบนี้

    info

    สถานะปัจจุบัน

    บทและเสียงพร้อมสำหรับ production แล้ว ขั้นตอนวิดีโอยังรอ CapCut batch ต้นทุนรวมอยู่ที่ประมาณ ฿0.30 ต่อวิดีโอ
